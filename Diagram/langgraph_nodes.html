ClaimBridge - LangGraph State Machine: 5 Nodes

📊 State Transitions Through Nodes

Node Input State Processing Output State
1. Validate claim_data, tenant_id Check required fields, member exists validation_result = {is_valid: true/false}
2. Retrieve claim_data + validation_result Embed query + VectorDB search (tenant filter) retrieved_policies = [top-5 chunks]
3. Generate claim_data + retrieved_policies LLM chain with tenant-specific config member_summary JSON (plain language + citations)
4. Quality Check member_summary + claim_data Rubric evaluation (7 dimensions) quality_score, pass/fail decision
5. Publish member_summary + quality_score INSERT DB + MCP audit log published = true, status = PUBLISHED

🎤 Interview Talking Points

"I designed this as a LangGraph state machine with 5 discrete nodes. Each node is a testable, independent function that reads and updates the state. If validation fails at Node 1, we immediately return an error — we don't waste API calls. If Node 4 quality check fails, we flag for human review. This is production-ready error handling."
